# Анимации

Требование владельца: **идеальная плавность — ни одного фриза**, «как в видеоролике».
Ориентир — сайт студии Promotion: всё анимировано и «вылезает», но гладко.

## Общие правила

1. Анимируем только `transform` и `opacity`. Никакого анимированного `filter`,
   `height`/`top`/`margin`/`width` — это главный поток и рывки.
2. Движение — то, что ведёт **композитор** (отдельный поток браузера): Web Animations
   и CSS-переходы по `transform`/`opacity`. JS-цикл, двигающий элементы, — только
   там, где без него нельзя (наклон визитки), и только пока что-то движется.
3. **React во время движения не перерисовывается.** Главная рисуется один раз;
   движок пишет в DOM сам (шапка, индикатор). Общее состояние секций — `lib/store.ts`.
4. **В момент жеста главный поток делает минимум** — всё готовится заранее, в покое.
5. Слои (`will-change`) — только у того, что двигается при следующем жесте.
6. Эффекты наведения — только при `finePointer()`; при `reducedMotion()` — без движения.

## Переход между секциями (`src/pager/engine.ts`)

Правило владельца — в `AGENTS.md`. Переход A → B (вниз; вверх — зеркально):

| Что | Анимация |
|-----|----------|
| секция B целиком | `translateY(±H → 0)` — приходит на весь экран |
| фон A (`.bg`) | `translateY(0 → ∓LIFT·H)` + `scaleY(1 → LIFT)` от края, обращённого к B — низ фона идёт ровно по краю B: одна граница, без щели и наезда |
| контент A (`.content`) | `translateY(0 → ∓H)` — **со скоростью B**, не своего фона |
| элементы контента A | сборка в обратной перемотке (`direction: reverse`) |
| элементы контента B | сборка вперёд |

- **Одна временная шкала**: у всех анимаций перехода одна длительность `DURATION`
  (1000 мс) и линейное время; кривые — внутри ключевых кадров (`EASE` у секций,
  `ITEM_EASE` у элементов). Поэтому разборка/сборка точно привязаны к
  перелистыванию, а жест назад посреди перехода — просто `reverse()` всех анимаций
  с текущей точки.
- **Окна элементов**: элемент `i` из `max` начинает в `START + i/max · min(SPREAD, max·0.06)`
  и длится `WINDOW` доли перехода. Блок — сдвиг `SHIFT` (90px) + прозрачность, строка
  заголовка под маской — сдвиг 110% без прозрачности. Сдвиг — по направлению
  перехода (вверх листаем — элементы приходят сверху).
- **Жесты во время перехода**: назад — разворот; вперёд во второй половине —
  ставится в очередь (следующая секция сразу после этой), в первой — игнор
  (один взмах тачпада не листает две секции).
- **Шапка и индикатор** меняются на середине перехода (граница под шапкой).
  Риски индикатора: длина — `scaleX`, красный цвет текущей — прозрачность второго
  слоя (`::after`), только transform/opacity.
- **Первое появление** после загрузки — сборка первой секции без движения, 1300 мс.
- `prefers-reduced-motion` — мгновенная смена секции.

**Разметка секции** (`Pager.tsx`): `section.page` → `.bg` (фон) + `.content` → `.inner`.
Элементы сборки — `r(i)` (атрибут `data-r`) и `<Lines>` (`data-r-line`). На элементе
с `data-r` не должно быть своего `transform` — его перекроет анимация.

### Что сделано ради плавности

- **Анимации собраны заранее.** `new Animation(new KeyframeEffect(...))` строятся в
  покое (`anims()`/`prepare()`), в момент жеста — только `play()`. Разбор ключевых
  кадров — самое дорогое в `element.animate()`: обработчик жеста при CPU ×4 был
  8–24 мс, стал 1–4 мс. После `cancel()` анимация снова «пустая» и запускается
  повторно (после `reverse()` возвращаем `playbackRate = 1`).
- **Соседи наготове** (`placeNear`): через 120 мс после перехода секции cur±1
  становятся видимыми за краем экрана (`data-near`, `translateY(±H)`) со слоями
  (`will-change`). Жесту не нужно впервые рисовать секцию и создавать слои.
  Заминка от подготовки приходится на неподвижный экран — её не видно.
- В момент жеста не читаем раскладку (высота экрана кешируется по `resize`),
  `inert` и индикатор меняем не в кадре жеста.
- Прогрев при загрузке: 3 кадра все секции рисуются почти прозрачными (`data-warm`).

## Ввод (`src/pager/input.ts`)

Колесо/тачпад копится до `WHEEL_STEP` (40px), затем шаг. Инерция тачпада глотается
до паузы `QUIET` (120 мс), смены направления или нового взмаха (рост силы событий).
Свайп — от `SWIPE_STEP` (50px). Если контент секции прокручивается (телефон) — сначала он.

## Заголовки

Строка выезжает из-под маски (`.mask` — `overflow: hidden` с запасом под выносные
элементы букв). Букв по отдельности и курсора нет (решение владельца — ради плавности).

## Колесо бонусов (`src/sections/Wheel/`)

Анимации из макета Claude Design (там колесо крутилось 4 с) не переносили —
остались наши. SVG-колесо поворачивается **одним CSS-переходом** `transform`, 5.6 с,
`cubic-bezier(.12,.6,.08,1)` (быстрый старт, долгое торможение). Выигрыш выбирается
заранее (равные шансы), под указатель встаёт случайная точка сектора (±35%), плюс
6 оборотов. Угол накапливается — повторная прокрутка без скачка. Конец — `transitionend`.

## Визитка (`src/team/TeamCard.tsx`)

CSS-3D без WebGL. Слои: `.shadow` (размытие нарисовано один раз в `::before`, слой
только сдвигается) → `.hit` (зона курсора, не двигается) → `.tilt` (наклон до 7°) →
`.flip` (переворот `rotateY` 0.8 с без перелёта) → стороны с `.gloss > .spec` (блик).

- Наклон — цикл rAF, пишет `style.transform` напрямую, следование `FOLLOW` 0.14 за
  кадр (без пружинной раскачки); цикл останавливается, когда карта встала.
- **Свет неподвижный** (сверху-слева): блик сдвигается против наклона и ярчеет,
  когда карта повёрнута к свету. Пятно нарисовано один раз — меняются только
  `transform`/`opacity`.
- На телефоне — наклон пальцем (зажал и ведёшь); тап — переворот; если палец
  сдвинулся больше 10px — это наклон, не тап.

## Производительность (как мерить)

Боевая сборка: `npm run build` + `npx vite preview` (не `npm run dev`). Playwright +
Edge, экран 2560×1600 при масштабе 150% (`viewport 1707×1067`, `deviceScaleFactor 1.5`),
замедление процессора ×4 (`Emulation.setCPUThrottlingRate`). Сценарий: 7 переходов
вниз, 7 вверх, разворот посреди перехода. Метрика — **пропущенные кадры
композитора**: события `PipelineReporter` (категории `benchmark`, `cc`,
`disabled-by-default-devtools.timeline.frame`) с `args.frame_reporter.state =
STATE_DROPPED` и `affects_smoothness = true`. Смотреть, **где** пропуск относительно
жеста: в кадре жеста — задержка старта на кадр (движение без рывка), на неподвижном
экране — не видно, **в середине движения — недопустимо**.
Мерить несколько прогонов: OneDrive синхронизирует папку проекта и шумит.

Итог (2026-11-15): CPU ×1 — 0 пропусков в движении; CPU ×4 — пропуски почти только
в кадре жеста (1–2), в середине движения — единичные. Старая версия: 41–112 за переход.
